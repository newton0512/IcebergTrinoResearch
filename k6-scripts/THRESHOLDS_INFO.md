# Информация о порогах производительности (Thresholds)

## Настройка порогов

K6 использует пороги (thresholds) для автоматической проверки производительности. Если порог не пройден, тест завершится с кодом ошибки.

## Текущие пороги (реалистичные значения)

### PostgreSQL запросы (`postgres-direct.js`)
- p50 < 200ms
- p90 < 1000ms
- p95 < 2000ms
- p99 < 3000ms
- Ошибки < 1%

### Trino запросы (`trino-direct.js`)
- p50 < 1000ms
- p90 < 5000ms
- p95 < 10000ms
- p99 < 20000ms
- Ошибки < 5%

### Запись данных (`write-cycle.js`)
- p50 < 3000ms
- p90 < 8000ms
- p95 < 15000ms
- p99 < 30000ms
- Ошибки < 5%

### Проверка согласованности (`consistency-check.js`)
- Общее время: p50 < 8000ms, p90 < 20000ms, p95 < 40000ms, p99 < 80000ms
- Время записи: p50 < 3000ms, p90 < 8000ms, p95 < 15000ms
- Задержка чтения: p50 < 2000ms, p90 < 8000ms, p95 < 20000ms
- Ошибки < 10%

### Аналитические запросы (`analytics-queries.js`)
- p50 < 2000ms
- p90 < 8000ms
- p95 < 15000ms
- p99 < 30000ms
- Ошибки < 5%

### Задержки чтения (`read-delay.js`)
- Время ответа: p50 < 1000ms, p90 < 3000ms, p95 < 6000ms, p99 < 15000ms
- Задержка чтения: p50 < 500ms, p90 < 2000ms, p95 < 4000ms, p99 < 10000ms
- Ошибки < 5%

### Реальная нагрузка (`real-load.js`)
- Общее: p50 < 2000ms, p90 < 8000ms, p95 < 15000ms, p99 < 40000ms
- Чтение: p90 < 3000ms
- Запись: p90 < 8000ms
- Аналитика: p90 < 15000ms
- Ошибки < 5%

## Настройка порогов

### Отключение порогов (если нужно просто собрать метрики)

Удалите или закомментируйте блок `thresholds` в скрипте:

```javascript
export const options = {
  stages: [...],
  // thresholds: { ... }  // Закомментировать для отключения проверки порогов
};
```

### Изменение порогов

Отредактируйте файл скрипта и измените значения в блоке `thresholds`:

```javascript
thresholds: {
  http_req_duration: ['p(50)<500', 'p(90)<2000', 'p(95)<5000', 'p(99)<10000'],
  // Добавьте или измените пороги
},
```

### Запуск без проверки порогов (только сбор метрик)

Используйте флаг `--no-thresholds`:

```bash
bash k6-run-pipe.sh k6-scripts/postgres-direct.js --no-thresholds
```

## Понимание результатов

### Тест пройден успешно
- Все пороги выполнены
- Выходной код: 0

### Порог не пройден (но метрики собраны)
- Некоторые пороги превышены
- Выходной код: 99 (это нормально для нагрузочных тестов)
- Все метрики собраны и доступны для анализа

### Критические ошибки
- Высокий процент ошибок (>5-10%)
- Выходной код: 1 (это требует внимания)

## Рекомендации

1. **Для первого запуска**: Используйте `--no-thresholds` чтобы собрать базовые метрики и понять текущую производительность

2. **Для настройки порогов**: 
   - Запустите тест без порогов
   - Посмотрите фактические значения p50, p90, p95, p99
   - Установите пороги на 20-30% выше фактических значений

3. **Для CI/CD**: Используйте строгие пороги для автоматической проверки производительности

4. **Для анализа**: Всегда сохраняйте результаты в JSON, даже если пороги не пройдены

## Примеры

### Сбор метрик без проверки порогов

```bash
bash k6-run-pipe.sh k6-scripts/postgres-direct.js \
  --no-thresholds \
  --out json=k6-results/postgres-baseline.json
```

### Смягченные пороги для первого запуска

Временно измените пороги в скрипте:

```javascript
thresholds: {
  // Более мягкие пороги для первого запуска
  http_req_duration: ['p(90)<5000', 'p(99)<10000'],
  http_req_failed: ['rate<0.10'], // До 10% ошибок допустимо
  checks: ['rate>0.80'], // 80%+ проверок успешны
},
```

### Анализ результатов при превышении порогов

```bash
# Запустить тест (даже если пороги не пройдены)
bash k6-run-pipe.sh k6-scripts/postgres-direct.js \
  --out json=k6-results/postgres-results.json || true

# Проанализировать результаты
jq '.metrics.http_req_duration.values | {p50, p90, p95, p99}' k6-results/postgres-results.json
```

## Важно

- **Выходной код 99** - это не критическая ошибка, это означает, что пороги не пройдены, но все метрики собраны
- Всегда анализируйте фактические значения метрик в JSON результатах
- Пороги - это цели производительности, а не жесткие требования
- Реальные значения могут варьироваться в зависимости от нагрузки и состояния системы
